DECKARD / FIELD GUIDE

Help

Deckard indexes Markdown notes locally, then connects the people, projects, topics, tasks, and links you already write. Nothing leaves your machine.

This page is the quick glance; each section's Read more opens the full guide.

Quick start

New to Deckard? opens the walkthrough: six steps, each checked off as you do it.

Rather see it than read it? writes a tour of Deckard, dated from the day you make it, and opens it. Its README leads through ten notes, one a topic, each holding what it explains and ending with what to try.

Open a workspace

Deckard indexes saved .md files in every workspace folder. Open a note, then use the Deckard icon in the Activity Bar for Context, which shows related notes and more, the Outline, Tasks, and the Calendar.

Write a few tags

Plain tags such as #follow-up are enough. Add @mara-vale for people, or namespaced tags such as #project/neon-relay, when that structure earns its keep. Typing # or @ suggests the tags you already use.

Follow the connections

Cmd/Ctrl-click a tag to open its search page, run for Home and every tag, or open the Notes Graph to see what is attached to what. Hover or Tab to any button to see what it does.

The first time Deckard reads a workspace it says what it found: how many notes, open tasks, and tags. Deckard only reads saved files. Save a note to see it in the index, and run if anything looks slow: every step over 100 ms is listed there. When something fails, its message offers Open Log, where the details are.

Tags and people

Lightweight tags

A plain #tag on a heading, a task, or a line of prose is indexed with no setup. Tag names take letters, numbers, _, -, and / namespace segments; a number alone is not a tag, so a date such as #2026 stays text.

People and entities

@mara-vale names a person. #project/…, #topic/…, #organization/…, and #meeting/… name entities; any other namespace becomes one on first use. deckard.personMarker changes the marker, and deckard.entityNamespaceAliases folds one namespace into another.

Inheriting tags

A task takes the tags of the heading above it, and a heading takes the tags of the headings above that, along with the note’s front matter. A tag written in a body does not travel: not up to the heading, not across to its neighbors.

Associated tags

Tags written together on one heading, task, or line are remembered as related, and tags that meet under a shared heading count more lightly. Related Notes and Refine both rank with that evidence, normalized so a common tag is not promoted for being common.

Favorites and order

The heart on a tag keeps it at the top of the Dashboard’s tag list. Favorites always appear before the rest, whatever the sort; a custom sort is dragged, moved one place with Alt+Up and Alt+Down on the focused tag, or moved with Move to top and Move to bottom on a tag’s context menu. Every context menu opens from the keyboard too, with Shift+F10, the menu key, or Alt+Enter on the focused row or tag.

On cards

On search results, task rows, board cards, and Related Notes a tag is quiet monospace text that opens its page, or its menu with Shift+F10; the editor keeps its box.

In the editor

Tags are clickable, hovering one says how many notes and tasks use it and lists its most recent entries, and a heading shows how many entries share its tags. deckard.editor.hoverPreviews and deckard.editor.referenceCounts turn those off.

The editor

A note’s title bar carries Deckard’s button, which opens Deckard: Note Actions…: what can be done from where the cursor is. A daily note’s title bar also steps to the day before and after. Right-click the title bar to hide either. Right-click in a note for a Deckard submenu with the task on the line, the heading, Move to…, and Pin. Links, task dates, repeat rules, and block ids take your theme’s colors; editor.tokenColorCustomizations changes any scope ending in .deckard. A task’s metadata is drawn fainter than its words, and an open task that is overdue or due today says so at the end of its line (deckard.editor.dimTaskMetadata, deckard.editor.taskDueHints). The status bar counts the note’s words, or the selection’s, leaving out code, front matter, and task metadata.

Front matter

YAML at the top of a note tags the whole note: tags:, and the typed fields people:, projects:, topics:, organizations:, and meetings:, which map to @person and the matching #namespace/… tags. aliases: gives the note other names that [[links]] resolve, describes: makes it a hub note, and created: / updated: are the dates Deckard dates it by.

--- project: neon-relay people: [mara-vale, ren-kade] aliases: [Relay, The Relay] updated: 2026-09-20 ---

Deckard: Move Inline Tags to Front Matter collects a note’s inline tags into these fields. Use it when the context belongs to every heading in the note, since that is what a front-matter tag means.

Links and embeds

Wiki links

[[Note]] names a note by its file name without .md, or by an alias. [[Note#Heading]] opens a heading and [[Note#^marker]] one line. Typing [[ completes titles and aliases; typing #^ completes the markers a note carries.

Embeds

![[Note]] on a line of its own draws that note in the Markdown preview; ![[Note#Heading]] draws the section, ![[Note#^id]] the marked line, and ![[#Heading]] a heading of the note you are in. An embed inside a sentence stays the text you typed.

Renaming keeps links

Renaming or moving a note rewrites every link that named it, in the same step, so one Undo takes back both. Deckard: Rename Heading does the same for a heading. deckard.updateLinksOnRename turns it off.

Broken links

A link to a note that does not exist is marked in the editor with a Create note fix; a name two notes share is a warning, since it opens neither. lists the notes nothing links to, and every link that opens no note, with Create and Create all.

What counts as a note

A “note” in Deckard is an entry: a heading and what is written under it, a task, or a tagged line. deckard.noteBoundaries decides what a tagged line is:

deckard.noteBoundaries
SettingA tagged line isA search for that tag returns
line (default)a note of its ownthat line
headingpart of the heading above itthe heading holding the line
markedpart of the heading above it, unless it carries a ^markerthe heading, or the marked line itself

A tag written in prose is never copied onto the heading: it stays where it was written, and the heading answers for it because it contains that line. Tasks are outside all of this — a task is its own entry under every setting. Changing the setting reindexes by itself and writes nothing to your notes.

Parking

A note, heading, or task is parked when it is in a parked folder, or when a search for a parked tag would find it. It stays searchable with is:parked, and is left out of the Tasks view, the Task board, the calendar, rollover, Related Notes, the Notes Graph, and tag completion. Deckard: Park Note writes parked into a note's front matter; and add to deckard.parked.folders and deckard.parked.tags. To keep someday tasks out of the Tasks view, park status/someday.

Writing tasks

Checklist tasks

A task is an unordered checklist item: - [ ] Send the proposal, with -, *, or +, and [x] when it is done. Checking a box anywhere in Deckard writes the same checked edit into the note, including the ✅ date and the next occurrence of a repeating task, from the task editor as well.

The task editor

Deckard: Edit Task Cmd+Shift+Alt+T on a task line — and Deckard: Add Task Cmd+Shift+Alt+T anywhere else — opens every field at once: description, status, dates, priority, repeat rule, assignee, and a tag. Dates are taken in plain words: friday, oct 3, next week (its Monday), end of month, in 3 days, last friday, and in every other box that asks for a date too; the box says back the day it read and how far off it is. It is on the lightbulb too, as Edit task….

Steps

A checkbox indented under a task is one of its steps. Deckard: Break into Steps… — on the lightbulb, the Tasks view’s menu, and a card’s ⋯ — writes them one per line you type, after anything already under the task, in one change that Undo takes back. The task then reads 2 of 5 steps · next: Draft the email on its card and row, and opens to its steps in the Tasks view. On the board and in the Tasks view a plain step rides on its task instead of being listed on its own; one with a date, priority, person, or tag keeps its own card. Finishing the last step offers to finish the task, and finishing a task with open steps offers to finish them; nothing is completed for you.

Suggested steps

With a VS Code language model installed, Suggest steps in Break into Steps… asks it for a list you edit before anything is written. Only the task’s words are sent, and only when you choose it. deckard.tasks.suggestSteps turns it off.

Done from the keyboard

Deckard: Toggle Task Done Cmd+Shift+Alt+X completes the tasks under every cursor, or reopens them when all of them are done, with the ✅ date and the next occurrence of a repeating task, as one edit that one Undo takes back. A repeat rule Deckard cannot read is underlined on an open task, since completing it would start no next one, and the lightbulb offers the nearest rules it can read.

The / menu

Type / alone at the start of a line for what to write there: a task, a heading, a link or an embed, today’s note, a query block, a table of notes or tasks, or one of your templates, its questions as tab stops. deckard.editor.slashMenu turns it off.

Typing metadata

Type / after a space inside a task to pick a due date, a priority, a repeat rule, or a dependency without remembering the markers. Suggestions use the format the task already uses, or deckard.tasks.metadataFormat for a task with none.

Who a task is for

Write 👤 @dana on a task — or [assignee:: @dana] in a Dataview vault — to say who it is for. A name in the words is a mention, not an assignment. Search with assignee = @dana, is:assigned, or is:unassigned, and set deckard.me so is:mine finds yours — a task for nobody in particular is yours too.

Capture

Cmd+Shift+Alt+N, or Cmd/Ctrl+Shift+Alt+N, adds a task to today’s note from anywhere, completing tags as you type; puts it under a heading you choose in any note, the ones used last first, above that heading’s sub-headings. With words selected, Capture and Find start from them, and a capture from a note links back to it. It stays open when you click away, and brings back what you had typed if you close it.

Dependencies

🆔 a1 names a task, and ⛔ a1 waits for it. A task is blocked while something it waits for is still open, which is:blocked and is:blocking search and the Tasks view says beneath the task. is:waiting is for people, not dependencies: a task marked #status/waiting, or for someone else.

Task metadata

Deckard reads the Obsidian Tasks formats, both the emoji one and Dataview fields, and writes back whichever a task already uses.

Markers, in the order Deckard writes them
MarkerDataviewMeans

🔁 every week[repeat:: every week]Repeat rule; completing writes the next occurrence, with the task’s steps unchecked under it

A repeat rule reads as Obsidian Tasks writes it — every week, every Monday, every month on the 15th — and also every other week, every 2 weeks on Monday, Thursday, every month on the second Tuesday, and Deckard’s own every quarter and every weekend, any of them ending in when done.

A date written in a task’s sentence, such as by Friday, is read as a due date when the note is a daily note, but Deckard will not rewrite it: there is no marker it could safely change.

Tasks view and Task board

Tasks view

The sidebar’s Tasks lists the open tasks that need attention soon. Group by in its title chooses the axis: due status, priority, status, person, or any tag namespace, such as #context, counting the tags a task inherits from its headings and front matter. Drag a task onto another to rank it, or onto a group to join it — which writes the priority, the status, the due date, or the name into the task itself. Overdue lists the most recently slipped first, five at a time, with Show N more for the rest; Upcoming has a group for each day, and a task dropped on one is due that day. Done today, folded at the end, lists what you finished today; unchecking one reopens it. Reschedule All… says how full each day is, and can spread a group over the next five weekdays or keep three for today. Parked tasks are not listed.

Task board

shows tasks as columns by status, priority, due date, person, or the tags of a namespace you choose, as a list, or as a table whose columns you choose and whose headers sort. Dropping a card rewrites the task in its note; the board opens on is:open, and its search box narrows both the board and the list. Parked tasks stay off the board unless its search says is:parked. While few tasks carry a status, the board says so above the columns and offers the due-date grouping, which needs none. The search icon in the Tasks view’s title opens the board to edit what the view lists: change the search, then select Save to Tasks view, which keeps what the box shows even before Enter runs it; Cancel leaves the view as it is. List in Tasks view, in the gear, makes the Tasks view list the board’s search from any board; selected again, the view lists every open task again.

The board from the keyboard

The board is one Tab stop. Arrow keys move between cards; on a focused card, x completes it, t and m make it due today or tomorrow, d asks for a date, 1 to 5 set its priority, [ and ] move it a column, e opens the task editor, s breaks it into steps, and Enter opens its line, beside the board with Cmd or Ctrl. ? on any page lists its keys. Each card's ⋯ menu checks what the task is now and shows the key for each choice; the keys work in the menu too.

Editing many at once

Bulk edit, beside a results pane’s heading on a search page, completes, reopens, dates, or tags everything the search found. Deckard lists the results with every one chosen, so unpicking any leaves it alone, and the whole edit is one write.

What is due

A task's due date is written by its distance from today with the date beside it, Overdue 15 days · 2026-09-08, wherever a task is listed. The status bar reads 3 due today while anything is, 2 overdue, 3 due today when something has slipped, and opens the Tasks view when selected. deckard.taskReminderTime says the same thing once a day, at the first moment VS Code is open on or after an hour you pick. A task more than 30 days overdue (deckard.tasks.needsNewDateAfterDays) leaves the count and the Overdue group for a folded Needs a new date group, until it is given one.

Search

Find

Cmd+Shift+Alt+F searches notes, tasks, tags, and saved searches as you type, correcting a misspelled word against the words in your notes. Enter opens the result; a tag row opens its page. With nothing typed it starts with your pinned notes, then the five you opened last. Cmd+Enter opens the highlighted result beside the editor and keeps Find open; Alt+Enter links it where the cursor was; Cmd+. lists everything it can do. A task can be completed or dated without leaving Find. Find learns which result you choose for what you type, and offers it first next time, never above an exact title. When nothing has every word, it offers to capture what you typed to today’s note. A note counts as opened when it stays in the editor a moment, however it was opened, so Find and Recently opened rank what you really read.

Search pages

Opening a tag collects every entry that carries it, with the tags it is most often written with. Any other search opens the same kind of page. Each page has the same search box, with completions and a visual builder that can build anything the box can say: rows and groups, nested, each group matching all or any of its rows, and turned around with not.

Previewing results

A result shows three lines of its entry, and Show all opens the rest. When the words you searched for are further down, the three lines are the paragraph they are in, after a muted …. The gear’s Preview chooses None, 3 lines, or Full, and Format chooses rendered or the Markdown source.

Refine

Under the box, Refine counts what the results could be narrowed by, five of each kind until +N more shows the rest; Links to lists the notes they link to. Selecting a value adds it with AND; Alt-click adds AND NOT, and Shift-click adds OR, widening the value chosen before it. Every value writes ordinary query text, so a refined search can be saved or copied into a note.

Saving a search

Save beside the box keeps a search, which reopens on the page it was saved from and can sit on Home as a widget. Recent searches are kept too. Save stays in place until there is a search to save, and says so when focused. Once saved, Show Results on Home adds a widget that lists what it finds, and a saved search’s row on Home offers Show results until Home lists it.

Taking a result out. Export notes and Export tasks, beside Bulk edit over a search page’s notes or tasks and beside Save on the Task Board, takes everything the search found — not only the page on screen — as a Markdown table, a list with a link to each result, or CSV, and copies it or saves it to a file. Its first choice, Copy as live query block, copies the search itself as a deckard fence to paste into a note, where it stays up to date. The index itself never leaves the machine.

Query language

A query is what you type into Find, a search box, a query block, or an AI assistant. Terms combine with AND, OR, NOT, and parentheses; AND binds tighter than OR, adjacent terms are joined by an implicit AND, and - or ! negates a term. A bare #tag is a tag condition, a bare [[Note]] is a link condition, and a bare word is a text condition.

(tag = #project/atlas AND tag = @ren-kade) OR (tag = #risk/vendor AND text ~ "elevator")

Operators are =, !=, ~ (contains), !~, and > >= < <= for dates and priorities. A window such as 7d is compared by its far end, so updated > 7d means within the last seven days and due < 7d means due within the next seven, overdue included. Every operator has an opposite, so any one condition can be negated without NOT.

Query blocks

A deckard code fence keeps a live list inside a note. The Markdown preview replaces the fence with what the query matches; the editor shows the totals above it with Open search page. Deckard: Insert Query Block… writes one of a saved or recent search at the cursor.

```deckard sort=updated limit=10 tag = #project/atlas AND task = open ```

sort= any task column such as due or priority, dir=asc|desc, limit=10, and view=table columns=due,priority,for for the tasks as a table, with noteColumns=links,tasks,#status for the notes as one, follow the language name. Results refresh when any note changes, not only the one holding the block, and the fence stays ordinary Markdown everywhere else. Like any fenced code, a query block is not indexed, so the tags inside it are not counted as uses.

Related notes and the graph

Related Notes

The sidebar ranks the notes most related to the entry your cursor is in: shared tags first, then associated tags, then links and shared wording. Each result explains its own score, and can be linked into the note you are writing. Under them, Linked from lists the notes that link here, newest first, each line unfolding onto its section, and Open as search opens them all as a search. Each result previews the first line of what it says, with the words it shares with your note marked; the gear sets Preview to none, one, or two lines, and Daily notes to Hide, which leaves daily, weekly, and monthly notes out of both lists. Parked notes are not suggested unless the note you are in is parked. A note with no tags lists entries with similar wording instead, marked weak, and the tags they use, each with Add, which writes it where the cursor is, with Undo.

Outline

A tree of the current note’s headings with the tags on each, and 2/5 · ↩3 for the tasks under a heading that are done and the links that name it. It can follow the cursor, and a heading’s context menu opens or renames its tags. Deckard: Focus Section folds the rest of the note away from one heading, and keeps only the headings that carry a tag.

Notes Graph

Every note, task, and tag as a map. Focus → Around this note draws one note’s neighborhood instead, one to three hops out, following the editor as you move between notes. Reset graph can be undone for a few seconds. Parked notes are hidden until Show parked is on. Solid lines are wiki links you wrote; dashed are headings; dotted are shared tags. Only links I wrote hides the rest. Zoomed out, each group is named after the tags that set it apart; click a name, or choose it from Group, to pick it out.

Stats

What needs attention first: any note Deckard could not read, with why, the links that open no note, the tags that look like one idea spelled twice, and the notes nothing links to (parked notes aside). Then the index totals, each opening what it counts, with how notes, tasks, and open tasks moved over twelve weeks, how much is parked, the tags and notes you open most, how often tags are used, with the tags used once to merge, and which tags are written together.

Check My Setup

When something is not there and you are not sure why, writes up what your settings resolve to here: where notes are read from and whether that folder exists, what the last scan found and kept out, which notes could not be read, and whether deckard.me names anyone — each with what to do.

Home and pins

Three figures at the top say what is Overdue, Due today, and Open; each opens its search. The Dashboard opens on Home, a page of widgets you arrange, with a Tags tab beside it — the Home/Tags tabs at the top of the page. Widgets cover today’s note, quick add, your tasks, the Tasks view's list, saved and recent searches, recently opened notes, workspace totals, tag pairs, tags without a hub, new tags, what has gone quiet — people, projects, or any namespace, with a next action for a project with nothing open — and pinned notes. Customize in the view options rearranges them; each widget’s gear sets how many entries it lists and whether it pages. While Home is in front, the Context sidebar lists every widget it can add: a click adds it at the top of Home, outlined for a moment. Reset widgets… asks before it puts back the widgets Home starts with.

Pinning happens where the note is, since a note is an entry rather than a file: Deckard: Pin Note to Home pins the entry the cursor is in, the hover on a tagged entry offers it beside its related notes, and a search result offers it on right-click. Each says what it did with Undo beside it.

Renaming and tidying

Rename and merge tags

rewrites a tag everywhere it is written, leaving prose and fenced code alone. Renaming into a tag that exists is a merge, which says first how many entries each has and how many carry both. The box starts from the old name and says, as you type, whether the new one merges or is new.

Tags that look alike

Stats ranks the pairs that look like one idea spelled twice — a name written with two markers, in two namespaces, punctuated two ways, pluralized, or mistyped — each with Merge beside it. A tag’s own page says how else it is written, with Include in search and Merge.

Hub notes

A note whose front matter says describes: [project/atlas] leads that tag’s page, and its other fields are shown as the tag’s properties. Home lists the frequently used tags that have no hub yet, and a tag’s page without one offers Create hub note under its title. The entries that link to the hub are listed on the tag’s page too, marked Links the hub note, and the page counts the entries that write the tag’s name as a plain word, with Show them.

Before and after a write

A write that reaches more than one note opens in VS Code’s refactor preview first, where any change can be left out. puts those notes back afterwards, leaving alone any note that changed since.

Extracting and moving

Deckard: Extract Heading moves a heading, and everything nested under it, into a note of its own and leaves a [[link]] in its place. Deckard: Move to… moves a line, a task and its steps, or a selection under another heading, into today’s note, or into a new note, leaving a link or a [>] task behind.

Templates

creates a note from a file in your templates folder, filling in the date, the title, and anything the template asks for. Right-click a folder in the Explorer for Deckard → New Note from Template Here…, or to leave the folder out of Deckard and bring it back; both new-note commands are in File → New File… too.

Days, weeks, and months

Daily notes

Cmd+Shift+Alt+D, or Cmd/Ctrl+Shift+Alt+D, creates or opens today’s note from your template, and the previous and next commands step between the days that have one.

Carrying tasks forward

Set deckard.dailyNote.rollover to move or migrate and a new daily note takes the unfinished tasks of the last week's daily notes with it, oldest first, under a Carried over heading. Migrate marks each line left behind [>] with a link to today. A task’s steps come with it, nested under it; a step whose task stays behind comes on its own, at the top level. does it on request, with Undo beside what it says.

Reviews

A weekly or monthly note opens with a review written into it: what was completed, what slipped, what is coming up next, the notes written and changed, and the tags first seen, with sections of your own from deckard.periodicNote.reviewSections. It is ordinary Markdown, named by the days it covers, and rewritten in place when you run it again.

Calendar

A month in the sidebar, in weeks from the day deckard.calendar.weekStart names, Sunday unless you change it. A dot marks a day with a note; a number counts what is due, orange once the day has passed and gray after 30 days, and an outlined number what is scheduled. Turn on the day panel from the view’s … menu to see the chosen day’s note, tasks, and new notes below the month, each task with a Tomorrow button; a click then chooses a day, and a double-click or Enter opens it. The week beside a row opens that week’s note. A repeating task shows on each later date its rule lands on, marked ↻; deckard.calendar.showRepeats turns that off.

The calendar page

, or the button in the Calendar view’s title bar, opens the calendar across the editor: each day lists its tasks by name, the chosen day’s panel sits beside the month, or in the Context sidebar while it is open, and Week shows one week in full. Drag a task to another day to move its date there. deckard.calendar.showWeekends leaves the weekends out, here and in the sidebar.

Zen mode

Zen mode turns Deckard’s own chrome down without taking anything away. The decorative labels and the grid backdrop go, the borders and headings thin out, and each row’s file name and line fold away until you hover or focus the row. Every button, filter, count, and tag stays exactly where it was, and the folded text is still read aloud, still found by find-in-page, and comes back the moment you tab to the row.

Turn it on from the gear on the Dashboard, a search page, or the Task board, from the zen button in the title bar of any Deckard page, from in the Command Palette, or by setting deckard.zenMode. It is one setting for every Deckard view, and it works with whichever theme you use — zen decides how much frame is drawn, a theme decides its colors. , or Theme above Zen in the same gear, shows each of the eight themes on the open pages as you move through them, and keeps the one you choose.

Two things deliberately stay put. A task’s due date, priority, and the word overdue are the point of the row rather than chrome, so they never fold; and a search that cannot be parsed still says so. The one thing you give up is the line of query syntax under the search box — the query language above has all of it.

AI assistants

Deckard gives assistants inside VS Code four tools — deckard_query and deckard_list_tags to read, deckard_add_task and deckard_change_task to write — so Copilot in agent mode, or any other assistant using VS Code’s language model tools, can answer questions from the index Deckard already keeps. You allow the first call in each session. deckard.assistantTools turns them off.

For Claude Code and other MCP clients, deckard.mcpServer.enabled runs a local server on 127.0.0.1 with the same tools, and copies the command that adds it, token included. makes a new token, so every copied setup stops working.

A write is guarded twice. An assistant asks before adding or changing a task, every time, and nothing is written until you approve the exact line in the refactor preview Deckard’s own writes use. A change is refused if the line is no longer the task the index knows there, and takes any write back.

Deckard answers with what it has indexed: paths, lines, titles, and tags. It never sends your notes anywhere itself — an assistant reads the answer, and what that assistant does next is between you and it.

Privacy and source safety

Your Markdown is the source of truth. The search cache and a copy of each note as Deckard last read it are stored locally, under this workspace’s storage, and no note content is sent to any service by Deckard.

Deckard changes a note only when you use a task checkbox, edit a task, extract a tagged heading, rename a note, tag, or heading, carry tasks forward, write a review, edit a search’s results, or approve an entity tag. Every one of those compares what it is about to change with what was indexed, and refuses when the line has moved on. Writes that reach several notes are shown first and can be taken back with .

Favorites, sorting, pins, widget layout, and view counts live in VS Code’s own storage, never in your notes.

What names your notes is kept with the workspace. Favorite tags and people, pinned notes, saved searches, Home’s widgets, view counts, and your task order belong to the folder they describe, so opening another project cannot disturb them. How Deckard looks — sort modes, column counts, layouts, page sizes — is kept for the machine and is the same everywhere. Upgrading from 1.18 or earlier hands what was stored machine-wide to the first workspace you open.

Deckard never deletes a favorite, a pin, or a saved search on its own. If what one pointed at is gone, it stays until you run , which lists what points nowhere and asks first. Only what Deckard derived for itself — view counts and access order — is cleaned up automatically.

It is copied, too. A moment after each change Deckard writes a copy of what this workspace remembers into the workspace’s storage and keeps the last twenty. offers them newest first. writes the same thing to a JSON file of your choosing, and reads one back; each says what it holds and asks before replacing anything.
